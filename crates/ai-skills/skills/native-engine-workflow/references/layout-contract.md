# Native layout contract

- Build from the live production.catalog; external shell, HTML, JavaScript, Python, plugins and fonts in upstream packages do not become native commands.
- A4 595.275590551 × 841.889763780 pt; 15 mm = 42.519685039 pt. Preserve other requested formats exactly.
- Use 2–6 columns where useful, with aligned edges, legible type and non-overlapping panels. This is a design choice rather than an enforced column count.
- Derive text frame height from line count and explicit leading, plus internal padding and baseline tolerance. Check actual native composition; estimates alone do not prove fit.
- Page patterns: paired comparison; 3–4 independent matching cards; 3-stage growth sequence; photo + editable diagram + observation question; vocabulary strip + drawing journal. Choose according to content and budget rather than applying every pattern to every page.
- In planning JSON, commands describe native text/shapes and images describes separate assets. Respect the catalog’s current maxItems and resource limits; choose a smaller batch or reuse supplied/approved assets if needed. Reuse must be disclosed and relevant.
- Apply native font family/style, size and leading with type.char; paragraph direction/alignment with type.para. Keep captions, headers, footers and numbers separate from raster images.
- A successful scratch preflight and visual proof are required; unsupported ICC/CMYK/PDF standards must be reported accurately. Human educational review and paper proof remain acceptance steps when required.
