# Native design quality

Review the composition against the user brief: clear information hierarchy, aligned edges, consistent spacing, sufficient contrast, meaningful pictures and preserved visual identity. Treat page density as a deliberate choice. A sparse page and a multi-panel page can both be correct when they serve the content.

Use a small set of native type roles and color roles consistently. Select fonts actually available to the engine and supporting the required script. Separate Arabic and English frames when their direction or alignment differs. Keep text horizontal, readable and fully visible. For the school example use A4 210×297 mm and 15 mm margins unless the user specifies otherwise; these are defaults, not universal requirements.

Check each section, caption, arrow, frame, image crop and pupil response area. Check that numbered activities have a clear reading order in RTL and LTR contexts. Do not reduce type below the intended reading size to hide overflow: first reflow, enlarge the allocated area, split the instruction or reorganize the layout while preserving meaning. Recheck the private native draft before spending on images.

Inspect native and PDF renders, actual page geometry, font embedding, image resolution at placed size, and editability of labels. Screen appearance does not establish print color accuracy or physical paper output. Keep unverified print requirements visible. See references/layout-contract.md.
