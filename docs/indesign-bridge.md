# Optional real INDD export on Windows

DesignCraft writes its native `.designcraft` format, PDF and IDML directly. It does not implement a native INDD writer. The optional `designcraft_ai_runtime::indesign` bridge asks a normally installed, licensed Windows InDesign application to open engine-produced IDML and save a real INDD file through its documented COM document API. There is no online conversion service, renamed IDML, or Adobe implementation code in this bridge.

The bridge currently accepts native text and ungrouped native shapes only: no assets, linked text, data-merge sources, or groups. It requires clean native preflight and at most 1,000 pages / 4,096 objects and stories. This deliberately limited first adapter covers the original science booklet without allowing an imported package to read linked resources outside the selected output roots.

```text
cargo run -p designcraft-ai-runtime --example indesign_export -- SOURCE.designcraft DESTINATION.indd
```

Call `indesign::prepare(&mut session, output_path)` on the session thread, then `PreparedIndesignExport::run(timeout)` on a background worker. `prepare` verifies read/write authority for staging and write authority for output/audit, refuses existing output/audit files, and exports IDML into a new staging folder beside the destination. `run` retains those automation roots, checks the staged source hash, and launches a fixed PowerShell COM helper. Paths are environment data, never inserted into script source.

The helper opens IDML without a document window, saves a new staged INDD, closes it, and reopens the INDD. It checks page/story/text-frame/item counts, overset text and unavailable fonts. Sorted per-story SHA-256 values verify all normalized Unicode content, including Arabic; only paragraph newline representations are normalized. Each page's dimensions and native object bounds must match within 0.02 pt. The helper temporarily uses point units in the reopened document's unsaved view preferences; application preferences and the saved file remain unchanged. In the reopened document it inserts text and undoes it, changes a native path anchor and undoes it, then closes without saving those verification edits. Only after successful checks and native INDD signature validation does Rust publish the verified bytes through `create_new`; an existing destination is never replaced. An audit JSON file records verified counts, content/geometry evidence, source/output hashes or failure. Staged IDML/INDD remain available for inspection.

The helper never quits InDesign or changes application preferences. The timeout is bounded to 300 seconds; cancellation or timeout stops only the helper process. InDesign may retain an export document after interruption. Publication checks cancellation before creating the final file; a late cancel cannot hide an already committed export from the artifact report. Authentication, license, import dialogs and application errors remain normal InDesign behavior; no activation or license state is bypassed. Registration alone is not proof that conversion works. Non-Windows platforms return an unsupported error.

The October 18, 2026 local synthetic validation used InDesign 21.2.0.30. The original eight-page science IDML was saved as INDD and reopened with 8 pages, 52 stories, 52 editable text frames, 99 page items and 47 native shapes. All normalized Unicode stories matched; the maximum native object-bound difference was under 0.000000001 pt. Overset text and unavailable-font counts were both zero; text insertion/undo and path-anchor change/undo succeeded. These checks prove editability, source content and native geometry for that fixture; they do not establish exact glyph rendering or lossless compatibility for arbitrary InDesign features. IDML currently drops DesignCraft script labels; this warning propagates to the INDD audit/report. Keep the native `.designcraft` source. Adobe-produced validation files stay in ignored `outputs/` and must never be committed.

Adobe documents programmatic IDML workflows in its [automation overview](https://helpx.adobe.com/indesign/desktop/automation-and-scripting/document-automation/automated-workflows-overview.html), Windows VBScript support in its [scripting guide](https://helpx.adobe.com/indesign/desktop/automation-and-scripting/document-automation/automate-workflows-with-scripts.html), document opening in [Application.open](https://developer.adobe.com/indesign/uxp/dom/api/a/application/), and native saving/closing/undo in [Document](https://developer.adobe.com/indesign/uxp/dom/api/d/document/). The constants are documented by [SaveOptions](https://developer.adobe.com/indesign/uxp/dom/api/s/save-options/) and [FontStatus](https://developer.adobe.com/indesign/uxp/dom/api/f/font-status/).
